# Corridor à la maison — repères pour tout agent

Ce fichier est lu par chaque agent qui travaille dans ce dépôt. Il dit ce qui est déjà fait, ce qui est fixé, et comment livrer sans marcher sur le travail d'un autre. `CONTRAT_LECONS.md` prime sur ce fichier pour tout ce qui touche aux leçons.

## Avant toute chose

0. Lire `HANDOVER.md` : le passage de relais du 11 octobre 2026, avec l'état du dépôt, les décisions du mandat v0.3.1 et les tests à reproduire.
1. `git fetch origin` puis `git checkout -b <type>/<sujet> origin/main`. **`main` est la seule vérité, et le site publié est `main`.** Jamais de push direct sur `main`, jamais de force push.
2. Lire la section « État » ci-dessous et vérifier qu'elle correspond au dépôt : `git log --oneline -5 origin/main`, `const VERSION` dans `app/app.js`, `const CACHE` dans `app/sw.js`.
3. Regarder les pull requests ouvertes et les branches. **Un fichier touché par deux chantiers ouverts : on s'arrête et on le signale au fondateur.**

## Architecture : ce qui est fixé, à ne pas réinventer

- **Site statique, sans serveur, sans dépendance, sans bundler.** HTML, CSS et JS tels quels, pour tourner hors ligne sur une tablette Android. Seul `app/` est publié. Aucune donnée d'enfant ne quitte la tablette.
- **État** : `localStorage`, clé `kono-v1`, forme `{ schema: 2, setup, pin, voice, settings, profiles: [...], ecole, lastBackup, log }` (`ecole` = `{ id, classe, h, date }` ou `{ grandfathered: true }` ; `log` = 50 dernières erreurs). Un profil : `{ id, name, girl, dob, classe, parcours, couleur, created, progress }` ; `progress.resume` = la séance en cours (`lesson`, `i`, `steps`, `run`, `fish`, `gold`, `elapsed`, `synthetic` pour une révision), `null` sinon ; un item de `run.items` porte `done` quand il est résolu. **`id` est immuable** (4 caractères, base 32), il nomme les enregistrements et les phrases de Maman. La migration depuis la v0.2 vit dans `fromV02()` (appelée par `loadStore()` et par la restauration d'une sauvegarde) et marque les profils migrés par `legacy` ; `migrateDB()` rattache ensuite les enregistrements et les phrases de Maman aux profils. **Ne jamais renommer la clé `kono-v1` ni la base IndexedDB `kono`** (magasins `clips` et `recs`) : ce serait perdre le suivi des enfants.
- **Enregistrements** (`recs`) : champ `profile` = id du profil, `heard` = écouté par un parent. **Phrases de Maman** (`clips`) : clé `<phrase>` pour les phrases communes, `<phrase>@<profil>` pour celles marquées `perChild` dans `app/phrases.json` (`bonjour`, `fin`).
- **Routage** : `lesson.parcours` est un `id` de `app/parcours.json`. L'index est au `schema: 2`, avec `escales` par parcours et `version` au format `S<n>-AAAA-MM-JJ`. L'application lit encore un index v0.2 le temps d'une mise à jour et refuse tout autre schéma. **L'âge propose la classe, le parent la confirme : la classe tranche.**
- **Dessin de l'interface (v0.4.0)** : tout passe par les variables de `:root` dans `styles.css` (`--bg`, `--sand` en accent, `--paper`, `--ink`, `--river`, `--shadow`, `--shadow-sm`). Règles tenues par `tests/ecrans.py` : aucune bordure en pointillés, aucune ombre dure (`0 n 0`) sur ce que l'enfant voit ; relief = ombre douce + enfoncement de 2 px au toucher. Un seul mouvement par écran (la pinasse sur la carte, Kono en séance) ; la fête n'existe qu'à la fin de la séance et disparaît en mode calme. Le mode contraste redéfinit `--bg` en blanc.
- **Thèmes** : `THEMES = bleu, orange, vert, violet` dans `app.js`, variables et sélecteurs `body[data-child="<couleur>"]` dans `styles.css`. La couleur est une préférence du profil, jamais une identité, jamais un critère de routage. La fiche est nommée par l'application d'après la couleur du parcours (`ficheOf`), jamais dans le texte d'une leçon.
- **Service worker** (`app/sw.js`) : cache `kono-<VERSION>` ; les fichiers de base, `parcours.json`, l'index, les progressions, les images et **toutes les leçons de l'index** sont préchargés à l'installation. **Toute nouvelle version change `VERSION` dans `app.js` et `CACHE` dans `sw.js`, avec le même numéro.** Le service worker s'enregistre en HTTPS et sur localhost, avec `updateViaCache: 'none'` ; les fichiers « frais » (moteur, styles, leçons, index, `parcours.json`, `ecole.json`, progressions, manifestes) sont demandés avec `cache: 'no-cache'` : revalidés à chaque ouverture en ligne, pris dans le cache hors ligne. Une publication est donc vue dès la première ouverture avec internet, sans vider le cache ; `tests/maj.py` le prouve, et la vérification après fusion le refait sur le site publié avec un profil qui avait la version précédente en cache.
- **Lancement** : `index.html` porte un style en ligne (fond sable, écran d'attente `.boot` avec `icons/icon-512.png` et le nom) affiché avant `styles.css` et `app.js` ; `boot()` remplace `#app`. Les icônes ne se dessinent pas à la main : `python3 tools/build_icons.py [--android <res>] [--play <dossier>]` les rend par Chromium depuis `const KONO` (yeux ouverts, sans sourcils) : `icon-<n>.png` (any, Kono à 82 %), `icon-maskable-<n>.png` (maskable, Kono à 58 %, dans le cercle sûr de 80 %) et, pour l'enveloppe, `ic_launcher`, `ic_maskable`, `splash` ; `tests/ecrans.py` vérifie tailles, fond, présence de Kono et zone sûre. Changer Kono, c'est relancer l'outil et reconstruire l'enveloppe.
- **Liste fermée** : types d'étapes, sortes d'automatismes (`kinds`), dessins (`show`) et champs sont ceux du README § 4 cité par le contrat et de son annexe A, vérifiés par `tools/check_lessons.py`. Un besoin nouveau se traite d'abord dans l'application et dans le script de contrôle, ensuite dans l'annexe, enfin dans les leçons. Il n'y a pas de `docs/FORMAT.md` : le contrat est le seul document de format.
- **Identifiants** : un identifiant de profil, de leçon, de parcours, d'escale ou de phrase (`voix/registre.json`) ne se renomme jamais et ne se renumérote jamais. Les leçons nouvelles s'appellent `<parcours>-s<n>-<mot>` ; `bleu-s0-dizaine` et `orange-s0-amis10` gardent leur nom.
- **Ordre des séances** : `ticketState(p, id)` est la seule règle (première non faite = du jour ; suivantes verrouillées ; faites refaisables ; révision jamais verrouillée) ; l'espace enfant, la fiche d'escale et l'onglet Programme la lisent tous. Une escale se lit par `escaleLessons(pid, n)` (champ `escale` de l'index).
- **Carte du voyage** : la pinasse avance d'une séance terminée à l'autre (révisions comprises) sur les escales du parcours ; Ségou après 4 séances (voulu : le texte de lecture y arrive). Géographie : Bamako, Ségou, Mopti, Tombouctou, Gao sont sur le Niger ; **Djenné est sur le Bani**, affluent qui rejoint le Niger à Mopti : la carte dessine le Bani et y place Djenné (point sans tampon) dès qu'une escale s'appelle Mopti ; le Niger continue après Gao, aucun texte ne doit dire qu'il s'y arrête.
- **Rapport** : le texte (format 2, `report()`, rubriques 1 à 7 inchangées depuis le format 1 plus la rubrique 8, maîtrise) et le fichier `rapport-2` (`reportData()`, clé `maitrise`) portent les mêmes chiffres ; `tools/tableau_classe.py` lit `rapport-1` et `rapport-2`. Ajouter une rubrique, c'est un nouveau numéro de format, dans les deux.
- **Réglages d'affichage** : `S.settings.gaucher`, `calme`, `contraste` → classes `gaucher`, `calme`, `contraste` sur `body` (`applySettings()` au démarrage et à chaque changement) ; tout le rendu est dans `styles.css`. `calm()` vaut aussi quand le système demande moins d'animations.
- **Juge** : `verdict(st, val, tries, left, forceWhy)` est pur (reveal ou retry avec explication, aide, dessin) ; `makeJudge` ne fait que l'écran autour. Les fonctions pures sont exposées dans `window.__kono.unit` pour `tests/unite.py`.

## Pièges connus, pour ne pas les repayer

- **Pages** : une organisation GitHub a trois noms ; seul l'identifiant (celui de l'adresse) fabrique `https://<id>.github.io/`. Le renommage de l'organisation ne republie pas le site : relancer le workflow (`workflow_dispatch`).
- **Service worker** : à la toute première ouverture, la page n'est pas contrôlée ; ce que l'application demande elle-même avant le `claim` n'est pas en cache. D'où le préchargement de toutes les leçons à l'installation.
- **Données** : le suivi, les enregistrements et la voix de Maman sont liés à l'adresse du site. Changer d'adresse après installation sur une tablette, c'est repartir de zéro.
- **Actions** : un compte GitHub verrouillé pour facturation refuse tout job, même sur un dépôt public.
- **Windows** : lancer les outils et les tests avec `python -X utf8` (sinon cp1252 altère les textes et `build_audio.py` pollue le registre) ; captures d'écran dans un dossier court (limite de 260 caractères) ; comparer les empreintes depuis `git cat-file blob`, jamais depuis l'arbre de travail (`core.autocrlf`).
- **Deux lignées d'`app.js`** : ne jamais les fusionner ; mesurer les deux sens en lignes modifiées et réappliquer le plus petit delta, fonction par fonction.
- **Playwright hors ligne** : la navigation témoin (`example.com`) se fait dans un autre onglet ; dans le même onglet, la page d'erreur de Chrome fait échouer la navigation suivante (« interrupted by another navigation to chrome-error:// ») et fait croire à une panne du hors ligne.
